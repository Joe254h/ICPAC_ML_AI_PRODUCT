# Repository audit and integration record, 25 October 2026

Scope: integrate the frozen pre-refit ICPAC Week-2 model (`ICPAC_WEEK2_WEB_MODEL_20261025`)
into the existing platform, make the ECMWF data page operational, add the experimental
verification and controlled model management, without rebuilding the application.

## 1. State found

**Architecture.** Next.js 16 frontend (`frontend/`, Vercel) calling a FastAPI backend
(`backend/app`, Azure Container Apps) through `/api`; one database (SQLite locally,
PostgreSQL in the cloud) holding JSON records by kind; product packages under `RUN_ROOT`
with an optional Azure Blob copy; a background operation worker (`services/operations.py`)
with a scheduler (`services/automation.py`); scientific code in `climate_engine/`.

**Operational data flow.** ECMWF Open Data → `climate_engine/inputs/ecmwf_opendata.py`
(index-checked byte ranges, members 1–10, 168 h and 336 h, cropped, `ecmwf_s2s_tp_<date>.nc`)
→ `ECMWFS2SForecastProvider` (`climate_engine/forecasts/ecmwf_s2s.py`) →
`operational/pipeline.run_forecast` → features (`preprocessing/atmos37.py`,
`operational/ecmwf.py`) → model (`models/residual.py`) → package, maps, country summaries
(`products/`) → CHIRPS verification, bulletin drafts with human review and email approval.

**Model.** One registered model: the Atmos37 CatBoost candidate (378 trees, 37 inputs,
validation-period candidate, untested). Its AI/ML layer could never run: the seven upper-air
training steps were not supplied (`ecmwf.pressure.week2_steps_hours: null`), so every live
forecast was raw ECMWF + MBC, labelled "in progress".

**Incomplete or broken.**

* `fetch_pressure` existed but nothing called it: no upper-air input was ever acquired.
* The model in use was "production, else the newest candidate": registering a new candidate
  would have switched forecasts silently.
* `/data/ecmwf` listed downloaded files only: no published-run check, no upper-air status,
  no compatibility or input checks, no failure history.
* The Verification page quoted a 537-case study by hand (`verification.tsx`), superseded
  by the 551-case independent verification; no categorical, discrimination, probabilistic or
  uncertainty results were shown.
* The bulletin, the package and the layer pages described the Atmos37 model in fixed text
  (37 features, 378 trees, 2005–2021 ratios).
* Two tests (`test_inputs.py`) depended on the date they ran; they failed after 20 October.

**Security notes.** Writes require operator or admin (`api/access.py`); model files are
read on the server only (no static route serves `artifacts/`); provider keys live in
environment secrets. `POST /forecasts/run` runs synchronously on the backend container
(not on Vercel); long work belongs to `/operations`, which this change keeps (the upper-air
download runs only in background operations).

## 3. Scientific limitations that remain

* **Real-time compatibility.** The model was trained and tested on ECMWF S2S reforecasts
  (1.5°, ten perturbed members). Live input is ECMWF Open Data ENS averaged from 0.25° to
  1.5°. The service checks members, leads, accumulation, units, grid, values and the
  feature contract; it cannot show that the real-time system's climate matches the
  reforecasts. That is why runs from 2025 need a reviewer's confirmation, and why no live
  skill is claimed until live forecasts have been verified against CHIRPS.
* **Upper-air availability.** Whether ECMWF Open Data lists every upper-air field the model
  needs (q at 850 and 700 hPa in particular) is checked per run (`Check ECMWF now`, and at
  download). If it is not, the AI/ML layer waits and forecasts come from MBC.
* **Post-test selection.** The full correction was named default after the 2022–2024 scores
  were seen; MAM-protected was the preselected policy and did not beat it. Both are shown.
* **Extremes.** Weeks of 100 mm or more are rarely detected (POD below 0.1); the models are
  not suitable for extreme-rainfall warnings.
* **Rwanda.** The full correction slightly increased RMSE over MBC (−0.26%).
* **Sudan.** 813 cells labelled Sudan in the authoritative scoring mask lie outside the
  reference outline (mainly the Halaib triangle). They remain in the scoring mask as frozen;
  maps draw the official outline; no result was changed.
* **Refit.** The 2005–2021 refit is not integrated and none of these scores apply to it.
* **Probabilities.** Deterministic hybrids get no reliability, Brier or CRPS; those scores
  are the raw ECMWF ensemble's. No Brier skill score is given (no valid reference forecast).

## 4. What a forecaster does now

1. Data & Tools › ECMWF ensemble: check the latest published run and readiness.
2. Models: record the HPC independent test for the chosen policy, approve it, activate it.
3. Operations: run the weekly cycle; inspect the input checks on the ECMWF page.
4. For a 2025+ run whose checks all passed, confirm the real-time input on the Models page.
5. Verification › Experimental verification for the frozen evidence; Verification for live
   weeks scored against CHIRPS. Bulletin drafts keep their human review and approval.

Nothing here activates a model, publishes a forecast or changes a secret automatically.
